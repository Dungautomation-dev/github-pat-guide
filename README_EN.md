## 1. What is a GitHub Personal Access Token (PAT)?

A **Personal Access Token (PAT)** is a specialized credential string generated by GitHub that replaces your account password when authenticating with GitHub via:
- Git command line (over HTTPS)
- GitHub REST API / GraphQL API
- CI/CD pipelines and deployment scripts

### Why did GitHub deprecate password authentication?
Since **August 13, 2021**, GitHub permanently discontinued account password authentication for all Git operations over HTTPS. 

| Feature | Password | Personal Access Token (PAT) |
| :--- | :--- | :--- |
| **Revocation** | Changes affect all devices | Can revoke individual tokens independently |
| **Access Scopes** | Full, unrestricted account access | Granular scopes (read-only, repo only, gist only) |
| **Expiration** | Permanent until changed | Configurable lifetimes (7 days, 30 days, 90 days) |
| **2FA Support** | Incompatible with CLI | Fully compatible with Two-Factor Authentication (2FA) |

## 2. Token Types on GitHub

GitHub currently provides two types of tokens:

### 1. Personal Access Tokens (Classic)
- **Format**: Starts with `ghp_` followed by 36 characters.
- **Scope**: Account-wide permissions based on broad check-boxes (`repo`, `workflow`, `write:packages`).
- **Best for**: Rapid local development, CLI scripts, and legacy CI/CD systems.

### 2. Fine-grained Personal Access Tokens (Beta)
- **Format**: Starts with `github_pat_` followed by 82 characters.
- **Scope**: Can be scoped down to a single specific repository and granular action (e.g., Read access to Issues only).
- **Best for**: Enterprise environments, third-party integrations, and zero-trust security.

## 3. Step-by-Step Guide to Creating a Token

### Option A: Creating a Classic Token (Recommended)

1. Log in to your GitHub account.
2. Click your avatar in the top-right corner > select **Settings**.
3. In the left navigation menu, scroll down and click **Developer settings** (at the bottom).
4. Click **Personal access tokens** > select **Tokens (classic)**.
5. Click **Generate new token** > **Generate new token (classic)**.
6. Fill in the required details:
   - **Note**: A recognizable description (e.g., `Laptop-Work-Git-Push`).
   - **Expiration**: Select `30 days`, `60 days`, `90 days`, or `No expiration`.
   - **Select scopes**: Check the `repo` box (includes `repo:status`, `repo_deployment`, `public_repo`, `repo:invite`).
7. Scroll down and click **Generate token**.
8. ⚠️ **IMPORTANT**: Copy the token immediately and store it securely. GitHub will never display it again!

## 4. How to Use GitHub PAT with Git CLI

### Method 1: Interactive Authentication via Git Credential Manager
When running `git push` or `git clone`:
```bash
Username for 'https://github.com': <Your_GitHub_Username>
Password for 'https://github.com': <Paste_Your_PAT_Token_Here>
```
*Note: In the password prompt, paste your token (`ghp_...`). Git Credential Manager on Windows/macOS will securely cache it in the OS Credential Vault.*

### Method 2: Authenticating directly via Remote URL
You can embed the token directly into the remote URL:
```bash
# Push directly
git push https://<TOKEN>@github.com/<username>/<repo>.git main

# Set remote URL permanently
git remote set-url origin https://<TOKEN>@github.com/<username>/<repo>.git
```

## 5. Security Best Practices

1. **Never commit tokens into code**: Always add `.env`, configuration files, and token scripts to `.gitignore`.
2. **Apply the Principle of Least Privilege**: Grant only the permissions strictly required for the specific task.
3. **Set Expiration Dates**: Avoid creating permanent tokens whenever possible.
4. **Immediate Revocation**: If a token is exposed, immediately navigate to **Settings** > **Developer settings** > **Personal access tokens** and click **Delete**.
